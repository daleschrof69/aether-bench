# RCA — Deploy blocked at trigger_indie (HTTP 409 deployment_blocked)

## Problem statement
A deploy run was committed for deployment `mtk-qualcomm-tool` (deployment_id `9c43a84e-50eb-4ade-b9f9-daba078d4bcb`). The pipeline failed at the **trigger_indie** step before any build/deploy work could run.

## Evidence
- `trigger_indie` returned:
  `status 409: {"code":"deployment_blocked","error":"This deployment was blocked. If you believe this is a mistake, please contact support."}`
  (type `deployer_indie_4xx`, **retryable: false**)
- `describe_deployment_state` shows `deployment_status: "deleted"`.
- The deployment's last two runs both completed as `success` (last active run `437b2eb1-10b8-4517-8083-e35108f5e4dd`, image tag `d8svlsb6p6ps73fns040`). So the app code/manifests previously built and deployed cleanly — this is NOT a build or source regression.

## Root cause
The deployment itself has been **blocked / marked deleted at the platform level**. The indie deploy endpoint rejects the trigger with a non-retryable 409 (`deployment_blocked`) because of the deployment's blocked/deleted state — not because of anything in the user's source code, manifests, secrets, tier, or database.

## Why no automated fix is possible
- The failure is at the very first gating step (trigger), before source pull / build / deploy.
- The error is explicitly `retryable: false`; re-firing `resume_pipeline` would return the same 409.
- This block is not addressable by a manifest edit, a code change, a secret, or a tier change.

## Required action
This must be resolved by **Emergent support** — the deployment block/deleted state has to be reviewed and lifted on the platform side. Quote deployment_id `9c43a84e-50eb-4ade-b9f9-daba078d4bcb` and job_id `1a39e802-f59d-443a-8d9c-1a149f4650b6`. Once the block is lifted, the deploy can be re-triggered.
